# دستیار تحلیل و معاملات خودکار کریپتو (تبدیل) — نسخه شخصی

## ⚠️ سلب مسئولیت (حتماً بخوانید)
این ابزار **توصیه مالی نیست**. تحلیل‌ها صرفاً بر پایه‌ی داده‌های گذشته و روش‌های تکنیکال رایج تولید می‌شوند و **هیچ سودی تضمین نمی‌کنند**. معامله با سرمایه واقعی و اهرم همیشه ریسک از دست دادن بخشی یا تمام سرمایه را دارد. مسئولیت هر تصمیم معاملاتی، من‌جمله فعال‌سازی معاملات خودکار، کاملاً بر عهده‌ی کاربر است.

## این پروژه چیست؟
یک اپلیکیشن اندروید (Flutter) که:
- بازار کریپتوی صرافی **تبدیل (Tabdeal)** را برای نمادهای موجود در «لیست رصد» تحلیل می‌کند.
- از ترکیب چند روش مستقل تحلیل تکنیکال (روند EMA، RSI، MACD، ساختار بازار به سبک SMC/ICT شامل BOS و CHoCH، مناطق عرضه/تقاضا، الگوهای کندل‌استیک، فیبوناچی) یک **موتور تحلیل ترکیبی (Ensemble)** ساخته و فقط زمانی سیگنال صادر می‌کند که چند شرط مستقل هم‌راستا باشند.
- در صورت فعال بودن «معاملات خودکار»، طبق سیگنال و تنظیمات ریسکی که **شما پیش از هر بار فعال‌سازی وارد می‌کنید**، سفارش بازار واقعی + حد ضرر روی صرافی تبدیل ثبت می‌کند.
- تمام کلیدهای API فقط و فقط به‌صورت رمزنگاری‌شده روی خود گوشی ذخیره می‌شوند (`flutter_secure_storage`) و به هیچ سروری ارسال نمی‌شوند.

## ⚠️ محدودیت‌های بسیار مهم فنی
1. **بدون سرور = بدون اجرای واقعاً ۲۴ ساعته.** این اپ فقط داخل گوشی اجرا می‌شود. اسکن بازار، تحلیل، و اجرای سفارش فقط زمانی رخ می‌دهد که برنامه باز و در حال اجراست. حتی با خاموش کردن بهینه‌سازی باتری، اندروید ممکن است در شرایطی (کمبود حافظه، ری‌استارت، آپدیت) برنامه را متوقف کند. اگر اپ در لحظه‌ی رسیدن قیمت به حد ضرر بسته باشد، ممکن است آن حد ضرر با تأخیر یا اصلاً اجرا نشود — به همین دلیل، سفارش «حد ضرر» به‌صورت یک سفارش واقعی (STOP_LOSS_LIMIT) مستقیماً روی خود صرافی ثبت می‌شود تا حتی بدون اجرای اپ هم فعال بماند؛ اما تیک‌پرافیت‌های چندگانه (TP1/TP2/TP3) در سمت اپ مدیریت می‌شوند و بدون اجرای اپ عمل نمی‌کنند.
2. **اندپوینت Klines (کندل تاریخی) تبدیل به‌صورت رسمی در مستندات عمومی یافت نشد.** کد یک تلاش اولیه برای `/klines` انجام می‌دهد و در صورت شکست، به‌صورت خودکار از اندپوینت `/trades` (معاملات اخیر) کندل می‌سازد که دقت کمتری دارد. پیش از استفاده‌ی جدی، آدرس صحیح را از مجموعه‌ی Postman رسمی تبدیل (`github.com/Tabdeal-Exchange/tabdeal-api-postman`) تأیید و در فایل `lib/core/api/tabdeal_api_service.dart` اصلاح کنید.
3. **بدون یادگیری ماشین.** بخش ML (پیش‌بینی روند، تشخیص رژیم بازار و...) از فهرست اولیه‌ی پروژه حذف شد، چون آموزش/اجرای مدل با کیفیت تولیدی روی گوشی و بدون سرور عملی نیست. موتور فعلی کاملاً مبتنی بر قوانین شفاف و قابل ردیابی است.
4. **فقط بازار کریپتو، فقط صرافی تبدیل.** فارکس، سهام، فیوچرز، کالا و شاخص‌ها طبق تصمیم شما از دامنه پروژه خارج شدند.
5. **این کد کامپایل‌نشده تحویل داده می‌شود.** من (Claude) نمی‌توانم در این محیط یک APK واقعی بسازم. مراحل زیر را برای بیلد دنبال کنید.

## آماده‌سازی برای Cloud Build (GitHub Actions / Codemagic)
این پروژه شامل دو مسیر بیلد ابری آماده است، بدون نیاز به کامپیوتر شخصی:
- `.github/workflows/build-apk.yml` — با هر Push به شاخه `main`/`master` یا اجرای دستی (Run workflow)، به‌صورت خودکار `android/` را می‌سازد، وابستگی‌ها را نصب و `app-release.apk` را بیلد می‌کند و به‌عنوان Artifact + پیوست یک Release قابل دانلود می‌گذارد.
- `codemagic.yaml` — همان فرآیند برای Codemagic؛ کافی است ریپازیتوری را در Codemagic متصل کنید و ورک‌فلوی `android-apk-release` را اجرا کنید.

هر دو پیکربندی، پوشه‌های native (`android/`) را در لحظه بیلد با دستور `flutter create --platforms=android .` می‌سازند — به همین دلیل نیازی نیست این پوشه را در گیت‌هاب نگه دارید (در `.gitignore` هم کنار گذاشته شده).

### رفع خطاهای قبلی Build
اگر با نسخه‌های قبلی این پروژه به خطای زیر برخوردید، در این نسخه رفع شده است:

1. **`unable to find directory entry in pubspec.yaml: assets/`** — علتش این بود که پوشه‌ی خالی `assets/` (که فقط یک فایل مخفی `.gitkeep` داشت) هنگام آپلود از طریق مرورگر گوشی به گیت‌هاب به‌درستی منتقل نشده بود. چون در حال حاضر هیچ کدی از این پوشه استفاده نمی‌کند، ارجاع آن کاملاً از `pubspec.yaml` حذف شد (به‌صورت کامنت در فایل نگه داشته شده تا در آینده اگر فایل واقعی اضافه کردید، به‌راحتی فعالش کنید).
2. **`flutter_local_notifications requires core library desugaring`** — چون پوشه‌ی `android/` در این پروژه commit نشده و هر بار در لحظه‌ی Build توسط CI ساخته می‌شود، یک اسکریپت پایتون (`scripts/patch_android_desugaring.py`) اضافه شد که بلافاصله بعد از دستور `flutter create`، خودکار موارد زیر را در `android/app/build.gradle` (یا نسخه Kotlin DSL آن) تزریق می‌کند:
   - `coreLibraryDesugaringEnabled true` داخل بلوک `compileOptions`
   - وابستگی `coreLibraryDesugaring 'com.android.tools:desugar_jdk_libs:2.1.4'` داخل بلوک `dependencies`

   این اسکریپت idempotent است (اجرای مکرر آن مشکلی ایجاد نمی‌کند) و هم در `.github/workflows/build-apk.yml` و هم در `codemagic.yaml` صدا زده می‌شود.

## نحوه بیلد گرفتن APK روی کامپیوتر (اختیاری، اگر نخواستید از Cloud Build استفاده کنید)
1. [Flutter SDK](https://docs.flutter.dev/get-started/install) و Android Studio را نصب کنید.
2. پوشه `crypto_trader` را در کامپیوتر باز کنید.
3. چون فولدرهای native (`android/`, `ios/`) به‌صورت کامل تولید نشده‌اند (این کار نیاز به اجرای واقعی Flutter SDK دارد)، دستور زیر را در ریشه پروژه اجرا کنید تا Flutter آن‌ها را خودش بسازد:
   ```bash
   flutter create .
   ```
   این دستور فولدرهای `android/`, `ios/`, `web/` و غیره را می‌سازد بدون آنکه به `lib/` و `pubspec.yaml` شما دست بزند.
4. نصب پکیج‌ها:
   ```bash
   flutter pub get
   ```
5. بیلد نسخه‌ی قابل نصب:
   ```bash
   flutter build apk --release
   ```
   فایل خروجی در مسیر `build/app/outputs/flutter-apk/app-release.apk` قرار می‌گیرد.

## ساختار پروژه
```
lib/
  core/
    api/tabdeal_api_service.dart      اتصال امن به API تبدیل (HMAC-SHA256)
    models/                           مدل‌های داده (کندل، سیگنال، سفارش، پوزیشن)
    analysis/
      indicators.dart                 EMA, RSI, MACD, ATR, Bollinger
      market_structure.dart           BOS/CHoCH، مناطق عرضه/تقاضا، فیبوناچی
      candlestick_patterns.dart       الگوهای کندل‌استیک
      signal_engine.dart              موتور ترکیبی تولید سیگنال
    risk/risk_manager.dart            محدودیت ضرر روزانه/اکسپوژر/توقف خودکار
  services/trading_controller.dart    مدیریت وضعیت کلی برنامه (Provider)
  screens/                            صفحات UI (داشبورد، تحلیل، معاملات، پورتفولیو، تنظیمات)
```

## تنظیم کلید API تبدیل
1. وارد سایت تبدیل شوید و از بخش API، یک کلید با دسترسی «معامله» بسازید.
2. **هرگز دسترسی «برداشت» (Withdraw) را برای این کلید فعال نکنید.**
3. کلید و رمز را در بخش «تنظیمات» اپ وارد کنید؛ به‌صورت رمزنگاری‌شده روی گوشی ذخیره می‌شود.
